# Telegram AI Operator

Личный Telegram-ассистент: Telethon слушает входящие личные сообщения, а отдельный Telegram-бот используется только для администрирования.

## Перед обновлением

1. Сделай резервную копию текущего проекта и Railway Variables.
2. В Supabase SQL Editor выполни **полностью** `database/schema.sql` из этого архива. Скрипт идемпотентный: использует `IF NOT EXISTS` и `CREATE OR REPLACE`.
3. Проверь, что Railway использует одну активную Replica и один сервис с данным `BOT_TOKEN`.
4. Замени файлы проекта содержимым архива и запусти Deploy.

Приложение ожидает переменные Railway:

- `BOT_TOKEN` — токен отдельного управляющего Telegram-бота.
- `ADMIN_ID` — твой числовой Telegram ID; только он получает доступ к панели.
- `API_ID`, `API_HASH`, `TELEGRAM_SESSION` — пользовательская Telethon-сессия.
- `GROQ_API_KEY` — начальный Groq API Key (после запуска его можно заменить в панели).
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — Supabase.
- `AI_MODEL` — необязательно, по умолчанию `openai/gpt-oss-20b`.
- `AI_MODEL_FALLBACKS` — необязательно, по умолчанию `qwen/qwen3.8-27b`.

Не публикуй `.env`, токены, ключи или `TELEGRAM_SESSION` в GitHub.

## Важные правила

- Добавление контакта в allowlist и подтверждение согласия — разные действия. Ассистент отвечает только если контакт добавлен **и** `consented=true`.
- Плановые исходящие инициативные сообщения удалены. Ассистент проявляет инициативу только внутри диалога, после входящего сообщения.
- Входящие сообщения объединяются за настраиваемое окно тишины. Каждая запись ставится в очередь; ID сообщений сохраняются в Supabase, чтобы восстановить очередь после перезапуска. Тексты переписки в очередь не копируются.
- При ошибках ИИ/Telegram обработка повторяется с увеличивающейся задержкой. После нескольких неудач администратор получает уведомление; после восстановления — отдельное уведомление.
- Ключ Groq, заданный через панель, хранится в Supabase в зашифрованном виде. Шифрование зависит от `BOT_TOKEN` и `SUPABASE_URL`: не меняй их без предварительной замены/переввода Groq API Key.
- Не запускай два экземпляра с одной Telethon-сессией. При rolling deploy новый экземпляр ожидает освобождения блокировки старым, максимум 3 минуты. Фактический перерыв зависит от Railway и Telegram.

## Панель управления

В управляющем боте доступны разделы: состояние, поведение, ответы, контакты, память и последние сообщения, чёрный список, профили поведения, модели/API, диагностика, статистика, тестовый ответ, история системной инструкции и резервная копия настроек.

Все изменения сохраняются в Supabase. Для изменения настроек поведения и ответов повторный GitHub Deploy не нужен.

## Диагностика

- `/status` — состояние приложения и список разрешённых контактов.
- `/session` — проверка, что управляющий бот и пользовательская Telethon-сессия являются разными аккаунтами.
- `/add @username` или `/add TELEGRAM_ID` — добавить контакт без автоматического подтверждения согласия.
- `/consent @username` или `/consent TELEGRAM_ID` — отметить согласие после его фактического получения.
- `/list` — список контактов и статусы согласия.
- `/enable`, `/disable` — включение и остановка автоответов.
- `/prompt` — просмотр системной инструкции; `/prompt ТЕКСТ` — замена.

Проверяй Railway Logs после первого Deploy. Локальные проверки синтаксиса не заменяют интеграционный тест с твоими реальными Telegram, Supabase и Groq секретами.
