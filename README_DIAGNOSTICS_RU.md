# Диагностика личного Telegram-аккаунта

Обновление:
- Управляющий бот и пользовательская Telethon-сессия теперь явно идентифицируются при запуске.
- Входящие сообщения от управляющего бота и самого аккаунта Telethon игнорируются до проверки allowlist.
- Добавлена команда `/session` для администратора: показывает ID и username управляющего бота и личного аккаунта Telethon.
- Логи входящих сообщений теперь содержат sender_id, chat_id и account_id.

Порядок:
1. Заменить `app.py` в GitHub на файл из архива.
2. Выполнить Railway redeploy.
3. Написать управляющему боту `/session`.
4. Проверить, что ID личного аккаунта Telethon — это именно аккаунт, на который должны приходить сообщения.
5. Попросить разрешённого собеседника с ID 8859584614 написать обычное личное сообщение именно этому аккаунту (не управляющему боту).

Ожидаемая диагностика:
- Сообщение от управляющего бота будет проигнорировано с причиной `message from control bot`.
- Сообщение от разрешённого человека должно появиться как `Incoming private message received` с sender_id 8859584614.
- Далее должны идти `Generating AI reply` и `AI reply sent`.

Это диагностическое исправление не меняет данные Supabase, таблицы, согласия, настройки или ключи.
