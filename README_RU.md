# Telegram AI Operator — обновлённый MVP

## Что умеет
- Управление отдельным Telegram-аккаунтом через бота.
- Доступ к управляющим командам только у `ADMIN_ID`.
- Автоответы только собеседникам из allowlist.
- Groq API для генерации ответов.
- Последние сообщения читаются из Telegram; тексты переписок не сохраняются в Supabase.
- Очередь на каждого собеседника объединяет короткие серии сообщений вместо прежнего cooldown, который отбрасывал новые сообщения.
- Синхронные обращения Supabase вынесены в `asyncio.to_thread`.
- Health endpoint: `/health`.

## Согласие и прозрачность
Добавляйте человека в список только после ясного уведомления, что сообщения может обрабатывать ИИ, и получения его согласия. Не используйте скрытую имитацию человека. Если собеседник спрашивает, кто отвечает, инструкция по умолчанию требует честно сказать, что это ИИ-помощник.

## Файлы
`app.py` — приложение; `requirements.txt` — зависимости; `.env.example` — шаблон секретов; `database/schema.sql` — схема БД; `Dockerfile` — контейнер; `render.yaml` — пример конфигурации Render.

## Настройка Supabase
1. Откройте SQL Editor.
2. Выполните `database/schema.sql`.
3. Возьмите Project URL и серверный Secret/service_role key в настройки окружения хостинга.
4. Не публикуйте service role key и не используйте его во frontend.

## Обязательные переменные
`BOT_TOKEN`, `ADMIN_ID`, `API_ID`, `API_HASH`, `TELEGRAM_SESSION`, `GROQ_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. Дополнительные параметры — в `.env.example`.

`TELEGRAM_SESSION` даёт доступ к аккаунту. Храните её только в секретах сервера. При утечке завершите сеансы аккаунта и создайте новую строку сессии.

## Команды
- `/start`, `/help` — меню.
- `/status` — состояние.
- `/enable`, `/disable` — включить/выключить ответы.
- `/add @username`, `/remove @username` — управление списком.
- `/list` — список разрешённых.
- `/prompt` — показать инструкцию.
- `/prompt новый текст` — заменить инструкцию.

## Запуск
Python 3.12+:
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Создайте `.env` на основе `.env.example` и перед запуском задайте переменные окружения. Само приложение намеренно не читает `.env` автоматически. Не коммитьте `.env`.

## Проверка
1. Выполните SQL.
2. Добавьте все обязательные переменные в secrets хостинга.
3. Убедитесь, что `TELEGRAM_SESSION` авторизована.
4. Запустите приложение с выключенными автоответами.
5. Добавьте тестового собеседника, который дал согласие.
6. Проверьте `/status`, затем короткий тестовый диалог и `/disable`.

## Ограничения
Это MVP, не production-ready и не гарантия доставки каждого сообщения. Очереди живут в памяти и очищаются при перезапуске. Медиа, голосовые сообщения и групповые чаты не обрабатываются. При сетевых сбоях или лимитах внешних API ответы могут задерживаться. Render Free может засыпать — не рассчитывайте на постоянную работу 24/7 на бесплатном тарифе.
