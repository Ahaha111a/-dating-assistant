# Исправление ошибки Groq `json_validate_failed`

Причина по логам: Groq отклонял обычный текст модели HTTP 400, потому что запрос принудительно требовал `response_format={"type":"json_object"}`. В результате текстовый ответ не доходил до Telegram.

Что изменено:
- Убрано принудительное серверное требование JSON.
- Парсер принимает корректный JSON, JSON в markdown-ограждении и обычный текст.
- Поддерживаются поля `parts`, `reply`, `text` и `message`.
- Невалидная реакция игнорируется, но сам текстовый ответ сохраняется.
- SQL-схема Supabase и переменные Railway не меняются.

Проверка: `app.py` прошёл `python -m py_compile`; архив проверен на целостность.
