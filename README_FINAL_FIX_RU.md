# Финальное обновление надёжности Telegram AI Operator

В этом обновлении исправлена обработка ошибок генерации ответа и добавлена диагностика полного пути входящего сообщения.

## Что изменено
- Если основная модель Groq временно недоступна, возвращает ошибку лимита/перегрузки или другую ошибку API, приложение теперь пробует следующую модель из `AI_MODEL_FALLBACKS`, а не прекращает обработку после первой ошибки.
- Если модель вернула пустой/некорректный ответ, приложение также пробует следующую модель.
- В логах теперь видны этапы: сообщение принято, поставлено в очередь, взято обработчиком, отправлен запрос к модели, выбран резервный вариант или отправлен ответ.
- Обработчик очереди каждого собеседника защищён от незаметного завершения; события подтверждаются через `task_done()`.
- Исправлена устаревшая обработка результата ИИ в планировщике инициативных сообщений: функция возвращает структуру `parts`, а не строку.
- Сохранены отдельные очереди для разных Telegram ID; сообщения разных собеседников не смешиваются.

## Установка
Замените файлы проекта содержимым архива в GitHub, сохранив структуру каталогов, затем дождитесь нового Railway Deploy.

## Важно
Для резервного переключения должны быть заданы рабочие имена моделей в переменной `AI_MODEL_FALLBACKS` (через запятую). Если все модели Groq одновременно недоступны или ключ API исчерпал лимит, приложение не может гарантировать генерацию ответа — теперь причина будет явно видна в логах.

SQL-схему Supabase менять не требуется.
